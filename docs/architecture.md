# 架构说明

3DGSDownloader 是 Windows x64 原生下载工具。GUI 与 CLI 共用计划和下载服务；界面只提交用户意图，不直接执行网络传输或修改下载内核。

## 模块

| 目录 | 职责 |
|---|---|
| `apps/desktop` | Win32 窗口、任务列表、新建下载弹层、编辑草稿、动作绑定及后台服务组合 |
| `apps/cli` | 命令行参数、服务调用和结构化结果输出 |
| `core/domain` | 下载计划、不可变快照、唯一业务编辑历史和保存标记 |
| `core/application` | `PlanService`、`ActionRegistry`、参数 schema、任务队列、下载执行与资源偏好 |
| `adapters/sources` | 影石公开页面解析、资源描述和运行期下载地址 |
| `infra/net` | WinHTTP 请求、流式读取、超时及取消检查 |
| `infra/storage` | 计划和工作区 codec、原子保存、已有文件核对及异步 I/O |
| `ui/text`、`ui/accessibility.*` | DirectWrite 文本、编辑缓冲、中文输入和现有 UIA 适配 |
| `graphics` | Skia 栅格画布和 Vulkan 呈现，来源记录见该目录的 `provenance.json` |
| `resources/theme` | 语义颜色、字体、尺度与组件状态 token |
| `tests` | 领域、存储、网络、CLI 和视觉矩阵验证 |

Skia 通过原生 C ABI 绘制 RGBA 缓冲，再交给 Vulkan 呈现；`libSkiaSharp.dll` 不引入托管 UI。这不是完整的 Skia GPU 控件合成框架，也没有通用停靠或第三方插件 ABI。

## 数据所有权

每条任务拥有一个 `PlanService`，其中的 `DocumentStore` 是该任务计划和业务撤销历史的唯一所有者。`TaskListService` 管理任务集合和串行队列，选择、焦点、展开状态与编辑草稿由桌面宿主单独管理。

| 数据 | 所有者与持久化 |
|---|---|
| 分享链接、资源勾选、输出目录及文件名 | `DocumentStore`；可导出 `.3dgsdl.json` |
| 任务运行状态、进度、下载结果 | `TaskListService` 与 `transfer::Service`；不进入业务撤销 |
| 已确认的基础目录、最近目录和资源类别偏好 | 工作区；由 `WorkspaceWorker` 与任务快照一起保存 |
| 当前行选择、键盘焦点、未提交文本 | 桌面宿主的临时状态；不另建可编辑业务副本 |
| 带签名的资源下载地址 | `ResolvedSource` 的运行期内存；不写入计划或普通日志 |
| 绘制描述和帧数据 | 不可变捕获交给 `RenderHost`；渲染线程不访问可编辑计划 |

资源偏好使用语义类别，不能使用任务 ID、签名地址或用户修改的文件名作为键。首次推荐主模型与相机数据；成功创建并加入下载队列后，记住本次基础目录及勾选/取消勾选状态。取消新建、修改旧任务或补下载旧任务不改变确认偏好。

## 命令、编辑与异步结果

GUI 菜单、按钮、右键菜单和快捷键使用同一个 `ActionRegistry`。动作包含 `actionId`、文字、作用域、`enabled`、`disabledReason`、`checked` 和 `invoke`，执行时重新检查可用性。CLI 使用相同应用服务和业务校验。

`ParameterSchema` 描述路径、文本和布尔字段，以及单位、范围、默认值、分组、编辑权限和生效时机。当前控件是显式适配，尚未实现由 schema 自动生成整个界面的框架。

- Enter 或有效失焦提交，Escape 放弃草稿；一次独立有效编辑产生一条业务历史。
- 非法草稿保留可修正文本，不静默转换为默认值。
- IME 组合输入和文本编辑优先于工作区快捷键；文本内的撤销不重放业务命令。
- 撤销计划不删除已下载文件，也不会自动发起或回退网络任务。
- 异步解析、下载和保存结果携带会话、请求或输入版本；接收时核对归属，拒绝过期结果。

## 线程模型

UI 线程负责输入、布局、轻量状态提交和消息分发。网络、大文件读写、哈希、线程等待和 GPU 等待均不能放在 UI 线程。

| 执行位置 | 工作 |
|---|---|
| 下载 worker | 公开链接解析、流式下载、校验、文件发布和终态收据 |
| 新建解析 worker | 新建草稿的资源解析；关闭或更改链接后丢弃过期结果 |
| 存储 worker | 计划/工作区读写、已有文件检查与串行保存 |
| `FolderOpener` worker | 检查并打开捕获的任务目录，不读取当前选中行来替换目标 |
| 渲染 worker | Skia 栅格绘制、Vulkan 提交、呈现与资源回收 |

worker 不直接回写 `DocumentStore`，通过结果通知交回协调层。关闭窗口通过异步停止通知协调；UI 不执行阻塞 `join`，窗口在呈现资源释放前保持有效。

## 保存与下载结果

计划和工作区保存基于明确快照，同一保存目标串行提交。先写同目录临时文件，完成后原子发布；失败保留原文件和未保存状态。保存期间的新编辑不能被旧快照的完成消息标记为已保存。

原文件使用独立临时文件，完成长度/校验验证后以不覆盖语义发布。已有结果须核对历史收据、路径、长度和哈希才能复用；无关或被修改的同名文件报冲突。取消请求与实际取消分开，发布与取消在统一提交点协调，每次执行只能有一个终态。

工作区保存任务记录、确认偏好及结果；不保存业务撤销栈、未提交草稿、运行线程或临时签名地址。恢复时检查本地文件，不自动联网；再次下载时重新解析公开链接。当前不是完整的持久化在途任务 journal，也不支持跨进程断点续传。

## 验证约定

构建、数据正确性、实际交互和视觉分别验证。CTest 中的视觉矩阵与文本测试不能替代真实窗口、IME、焦点、文件夹打开和重启恢复检查。视觉比较固定窗口尺寸、DPI、语言及状态，行为比较固定输入序列、最终数据和历史变化；未运行的项目明确记录，不沿用历史结果冒充本次通过。
